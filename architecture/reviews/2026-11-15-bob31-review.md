## Is the deploy safe against rc.35 and rc.36?

Yes. These are the reasons:

1. **This deploy carries very little.** From rc.35 (47d5483) to 96aed95, the broker's and
   protocol's `src` change by five lines, the two above. rc.36's commit (08f0c6e) touches only the
   broker's and protocol's `package.json` versions. Everything else is `public/` (the dashboard,
   which the broker serves and which ships with it) plus tests and shots. There are no wrangler,
   migration, Durable Object schema or frame changes.
2. **The change is additive and only the broker produces it.** `waits` is a board read that only
   the dashboard calls (`app.js loadOverview`). Neither `packages/client` nor `packages/supervisor`
   calls it or names `WaitRecord`, so no installed client or supervisor parses the field, and no
   agent's MCP context grows.
3. **Nothing changes on the wire for agents or supervisors.** `ask` already took and stored
   `context`. An rc.35 or rc.36 supervisor's frames, board ops and run reports go to the same code.
4. **Order doesn't matter.** No release is waiting on this broker, and none needs it. A dashboard tab
   that is still open from before the deploy ignores the field until it reloads. After a reload it
   gets both halves together.

If the live broker is older than rc.35's (the run_remote deploy from the BOB-4 review), this deploy
also carries `run_remote`. That is the order that review asked for: broker first. It's safe too.

The usual cost applies: a deploy drops every agent's connection, and clients reconnect. That's
Casper's to ask for, once (Mario).

## Nit (no item)

`render()` now gives focus back to the answer form's **textarea** whenever focus was anywhere inside
`form.answer` (`app.js render`). If a direct `render()` (not a live frame, which `scheduleRender`
defers while the form has focus) ran while an option's radio was focused, focus would move to the
textarea. I found no path that does this today. A radio's `onchange` calls `check()`, not `render()`,
and Show less moves focus to its button first. If one turns up, restore focus to the same element by
name or index rather than always to the textarea.
