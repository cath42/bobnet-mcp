### Mario's hunch: the start-edge walk
The walk in question is `while (s > 0 && WORD.test(text[s-1])) s--` (`secrets.ts:157`). It goes quadratic
only when many spans that are all word characters sit inside one long `\w` run. With the patterns as they
are, that can't happen:
- **When a walk starts.** A walk starts only at a span whose start has a letter or digit before it and a word
  character at it.
- **Which spans can start there.**
  - Every token pattern starts at `\b`. `jwt` and the assignment start at lookbehinds that refuse a letter
    or digit.
  - A private-key BEGIN starts with `-`.
  - The only pattern with no left boundary is PuTTY's header, `PuTTY-User-…`, and it has a `-` at offset 5.
- **So each character is walked at most once.**
  - A walk from one span stops inside the previous span, at its last non-word character.
  - Or it stops at the previous span's start, when that span is all word characters (AWS, GitHub). Such a
    span starts at `\b`, so the character before it is not a word character.
- **The case that is quadratic.**
  - It needs a mark that starts with a word character: then `aREDACTEDaREDACTED…` with the mark
    `REDACTED` walks back to the start of the run for each mark.
  - That takes 327 ms at 20 KB and 33 s at 200 KB.
  - No caller passes such a mark. The only caller is `supervisor.ts:184`, whose `WITHHELD` starts with `[`.

### Notes, no action
- **Two different version sources.**
  - `resume()` compares the row's `to` (the tag's root `package.json`) with `ownPackage.version` (the
    supervisor's `package.json`).
  - They agree because a release bumps every package together. A release that forgot the supervisor's
    would report "running X, not Y" for an upgrade that worked.
- **A stand-in drops the event.**
  - An upgrade event is first redacted field by field, so a `failed` whose output holds a credential still
    arrives, marked.
  - Only when the stand-in goes does it carry no `req`, and the requester drops it. That is rare, and it is
    logged.

## Findings

### M1 (major): the clone is code the supervisor runs, and workers can write it
- **What the supervisor runs there.** It runs `git fetch`, `git show` and `git archive` in `upgrade.repo`.
  The clone's `.git/config` decides:
  - where `origin` is (`remote.origin.url`), which is the trust root of §3;
  - which commands git runs (`core.sshCommand`, `credential.helper`).
- **Who can write it.**
  - The rc notes suggest `~/Code/bobnet-releases.git`. That path is outside the guard. Workers' file tools
    are write-scoped, but a Bash `git -C ~/Code/bobnet-releases.git config …` goes to the classifier, not
    to a deny.
  - A clone shared with worktrees is worse: every worktree writes the same config.
- **What follows.** A worker that rewrites the clone gets its own code run as the supervisor, outside every
  guard, at poe's next `upgrade_supervisor`. ADR 0008 guards `<root>` for the same reason.
- **Fix for rc.42, no code (Mario's rc notes, Casper's config).** Put the clone under `<root>`, which the
  guard already denies to every worker:
  - make it with `git clone --bare <origin> ~/.local/share/bobnet/.src.git`;
  - set `upgrade.repo: ~/.local/share/bobnet/.src.git`.

  The dot-name keeps `runningRelease` and the build off it: they skip dot-names and touch only
  `.<tag>.partial`.
- **Fix in the next build.** `bin.ts:81` adds `config.upgrade?.repo` to `Policy.load`'s roots, so any clone
  that the config names is guarded. This is one line plus a test. ADR 0008 ruling 5.

### m1 (minor): the start-edge walk is quadratic for a mark that starts with a word character
- **Not reachable today:** the only mark starts with `[`. It would be reachable if a future caller passed a
  word mark.
- **The fix,** linear and tested. It is a forward cursor that keeps the start of the word run up to `s`:
  ```ts
  let walked = 0;
  let run = 0;
  // in the map:
  if (s > 0 && ALNUM.test(text[s - 1]!) && WORD.test(text[s]!)) {
    for (; walked < s; walked++) if (!WORD.test(text[walked]!)) run = walked + 1;
    s = run;
  }
  ```
  - With it, 200 KB of `aREDACTED` with the mark `REDACTED` takes 11 ms (33 s before).
  - Against the build, 120,000 fuzz texts × 3 marks give 0 differences.
- **When.** Backlog, with the next `secrets.ts` touch (Bearer/jwt m1 from A-fixes-3). Not rc.42.

### m2 (minor): a local second upgrade can race the first one's restart
- **How it happens.**
  - `ask` blocks other asks while it verifies, but `poke()` doesn't wait for that.
  - An upgrade waiting for idle can start `switchAndExit` during the second's fetch.
  - The second then overwrites `this.current`, gets `ok`, and starts a build that the exit 15 s later cuts
    short. It leaves no row, so nothing is reported for it.
- **Who can hit it.** A remote ask is itself "in progress" and so holds idle. Only this laptop's own
  orchestrator can hit it.
- **The fix.** After the verify, refuse when `this.current` is no longer waiting:
  `if (this.current && this.current.state !== "waiting") throw new UpgradeRefused(…)`.
- **When.** Backlog.

### m3 (minor): a restart mid-install reports nothing (Luigi's open question 1)
- **What happens.** A restart during the archive or the install leaves no `upgrades` row. So the requester
  hears nothing after `ok`.
- **What's left behind.** The `.<tag>.partial` stays until the next build of that tag clears it.
- **The fix.** An `installing` row, written when `run()` starts. `resume()` then sends `failed`, `start`:
  "restarted while installing", and removes the partial.
- **When.** Backlog. poe sees no `installed` notice and asks again. Not rc.42.
