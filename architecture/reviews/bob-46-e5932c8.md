# Review: BOB-46 (e5932c8), session order by latest spawn

Toad, 2026-11-16. **Signed off** for rc.38. Supervisor only; no protocol or broker change.

## The change
- `Boards.build` (packages/supervisor/src/board.ts ~535) sorts sessions by their latest worker's
  `created_at`; `started_at` stays the first worker's. `spawned` is passed to `sessionAt` in a copy,
  so the wire shape (`ProjectBoard.sessions`) is unchanged: additive-safe both ways.
- `sessionAt`: among holding spans, the latest spawn at or before the call wins; ties go to later
  list order (`>=`). A call in A's span after B's spawn but before A's re-spawn goes to B: right.
- `SESSIONS_WITH_RUNS` (`slice(-4)`) now keeps the sessions worked in last: the fix.

## Dashboard readers (packages/broker/public/app.js)
- `sessionsOf` (189): `named.at(-1)` is the session spawned into last: right. `prev`/`prev2` are
  the same kind by latest activity, a fair comparison.
- `sessionBars` (2500): order and `slice(-n)` follow activity; the current bar is last: right.
- `sessionRuns` (196): matches by name, sorts runs by their own `started_at`: order-free.
- Build lanes (252) and the steps view (398) sort by `started_at` themselves: unaffected.
- `backlogModel` uses `cur.started_at`: earlier, so more inclusive; still right.

## Luigi's open minor: `projects()` (179)
It orders projects by `sessions.at(-1).started_at`, which can now be old. Ruling: **not a blocker,
a chore for the backlog** (Peach). The fix is in app.js, a broker deploy: order by the max of
`started_at`/run ends, or by a `last_spawn` field the supervisor adds (additive). Ship rc.38 as is.

## Findings
None blocking; one minor (above), deferred.
