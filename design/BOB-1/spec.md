# BOB-1: release 1's screens, spec

Daisy, 2026-11-13. A clickable prototype of capabilities 2, 3, 4, 6 (Casper's gates), 7 and 8 on Helix's real
board, for Casper to accept or correct (BOB-1 #6). Luigi builds from this file, the prototype and
[notes.md](notes.md).

- **Prototype:** open `design/BOB-1/prototype/index.html` in a browser (works from `file://`, no server).
  It uses `packages/broker/public/style.css` as is, plus `prototype/proto.css` for the new parts; those rules use
  only style.css's tokens and move into style.css when built. Edits and captures live in memory; reload resets.
- **Data:** `sample/helix.js` and `sample/bobnet.js` are generated by `sample/extract.mjs` from the board files,
  read only (Helix: `~/Code/helix-navigator-picard` at 282cca2fe, 698 tasks, 103 drafts, 29 features, 3
  releases). `sample/records.js` holds what no board file has: LAND-49's six sessions, transcribed from Helix's
  close handoffs and git log, and the waits-on-Casper items from Helix's `lead/questions.md`. Three things are
  marked *example* on screen (a bug that blocks use, a pending permission, sessions' tokens): no
  record of them exists to sample. The `#source` screen names all of it; a strip under the header names it on
  every screen.
- **Screenshots:** `shots/<criterion>-<screen>-<width>.png` at 390, 1024 and 1440. Retake with
  `PLAYWRIGHT=<playwright-core dir> node design/BOB-1/shots/take.mjs [prefix]`.

## Layout

Header: BobNet, tabs **Overview · Waits on you (count) · Roadmap · Feature · Triage**, **+ Capture**, live
dot. On a phone the tabs scroll sideways (as today) and "Waits on you" comes second so its count is always in
view. Capture is on every screen.

## Screens

### Overview (`#overview`) (roadmap-view 6, waiting-on-casper 3; redone in round 1, notes 31-34)
It answers three questions in this order: what needs me, who is working on what right now, and where each project stands.
- **Needs you (count)**: one line per item that holds work up (kind badge, the question in bold and cut to
  one line, then project · feature · "holds up …" in red). It ends with a link: "5 hold work up · 7 more
  when you have time →" to Waits on you. Nothing held up: "Nothing is held up by you."
- **Working now (count)**: one line per agent with a state dot (green working, amber waiting on you), name,
  role, state when it isn't working, and tokens. Under that: project › feature id, session label › task id
  and title, with the feature and task linking to the Feature view. Leads and consults: "Other work (no
  session)". None running: "No agent is working."
- **Projects**: a full-width row per project with five cells: the name (to its roadmap) with laptop, lead
  and PO; **Release** (number, name, meter, features done of total); **Open now** (id and title clamped to
  two lines, criteria ticked, who is on it or "nobody on it"); **Next** ("Waits on you: Q-258" in amber
  when the next step is Casper's, then "Then Ready:" the next Ready feature); **Backlog** (items to triage,
  bugs, oldest).
- Desktop (wide main, 1320 px) and tablet: Needs you and Working now side by side, Projects under them. A
  project row has 5 cells on desktop and 2 per line on a tablet. Phone: everything stacks. A project's cells
  stack with their label on the left, and a Needs-you line wraps to two lines.

### Roadmap (`#roadmap/<project>`) (roadmap-view 1-4, 7-9)
- Project switch (segmented). Releases **numbered in their order** (1, 2, 3), each with a state (open, all
  done, closed), features done of total, and a counts line: backlog items in it, open bugs, oldest age (links to
  Triage).
- Features in a table, **numbered in the board's order**. A feature with no order on the board gets an
  *italic* number and follows the ordered ones by id. Columns: # and feature (id, title, who is on it now),
  state (draft, ready, open, in review, done), criteria (meter and "52 of 81"), tasks done of total.
- The **open feature** has a green edge and says who is on it, or "nobody on it now".
- A **Done feature with unticked criteria** shows done, its real count, and "Done, criteria not ticked".
- More than three done features in a release fold into one row naming their numbers ("21 done (1–19, 21–22):
  show them"), so the open work is at the top on a phone.
- "Not in a release" comes last, unnumbered.
- Phone: each feature row becomes a card (style.css's `table.stack`); done rows show only number, id and title.

### Casper's gates (`#roadmap/<project>/edit`, `#triage/<project>/edit`) (board-writes C2, 4, 5)
- **Edit your gates** turns on: a banner saying what the gates are and that the rest is a request to the PO;
  per release **↑ Earlier / ↓ Later** and **Close release**; per feature a **Release** select (any open release
  or none). On Triage, the same button gives each backlog item a Release select.
- Each change saves at once, says so in a toast with **Undo**, and is recorded as Casper's. A moved feature goes
  last in its new release's order; the PO orders it.
- **Close release**: a dialog. All done: one sentence and Close. Features not done: each named, with a select
  for where it goes (a later release, by default the next; or out of any release). Close is the danger colour.
  A closed release stays on the roadmap, folded, and drops out of the move selects.
- Phone: the dialog is a bottom sheet with full-width buttons.

### Feature, the steps view (`#feature/<id>`) (steps-view 1-8)
- Picker of features that are open or Ready, across projects.
- Head card: id, project, release and order number, state, title, criteria meter, tasks done, sessions, who is on
  it now.
- **On it now** (when anyone is): a card with a green edge, one line per agent with a state dot, name, role,
  state and tokens, then session › task id and title (notes 28-30).
- **Next step banner** at the top (where a phone sees it first), linking to the end of the chain.
- **Sessions as a vertical chain, in the order they ran.** Each step: a dot in its kind's colour (style.css's
  `--k-design`, `--k-build`, `--k-review`, `--k-retro`), kind, label (Design, Build 1, Review 1, Build 2, Review
  2, Fixes), start and end with duration, state (running, closed, waiting). A closed one shows its outcome
  in one line: **need** (none in green, casper in amber, with the items), blockers and majors, minors fixed or
  tasks sent back, tasks closed or moved, then its total tokens, muted. A running one shows its agents live (model, laptop, time, **tokens**,
  context, last checkpoint). Each agent line also shows role, state and the tasks it is on. A
  waiting agent's line is amber. Then a sentence of summary, links (handoff, the close commit, Remote Control
  where there is one), and **Tasks it moved**, folded except on the latest session, each with the status the
  session left it in and its criteria now. On a running session the list is **Tasks it is on**.
- **Agents on tasks**: a task row with an agent on it has a green edge and, under the title, one line per
  agent: dot, name, role, state, tokens. In the board's list beside the chain the line also gives the session
  label. The source is the session and tasks each worker declared at spawn. The sample's running build on
  LAND-49 (Fixes 2: Marvin on 49.19, Howard on 49.14, waiting on his permission) is *example*.
- The chain ends on a dashed **Next** step: what the feature's state calls for, or "Waits on you" with the
  question, the recommendation and what comes after.
- Beside the chain (desktop, sticky) or under it (tablet, phone): **In no session yet** (tasks no session has
  touched) and **All tasks as the board has them now** (open on desktop, folded below 1100 px).

### Waits on you (`#waits`) (waiting-on-casper 1-3, bugs 3, C8)
- Filter by project (with counts). Two groups: **Holds work up** (red edge) and **When you have time**,
  each oldest first.
- Each item: its kind (question, action, review gate, permission, bug · blocks use), id, project and feature,
  age; the question in bold; the recommendation; what it holds up (red), only on items that hold work up; "Needed before …" (muted) on
  one that waits for a later milestone (notes 35); who asked; the session that closed
  on it (need: casper), if any; a link to where it is answered. No answering here.
- A session closed with need: casper shows on the question it waits for, not as a second item.
- Empty: "Nothing is held up by you." The count leaves the tab.

### Triage (`#triage/<project>`) (capture 4-6, bugs 2)
- Project switch; filters All, Bugs, each release, No release, with counts. Totals: backlog items, open bugs,
  oldest, median age, captured this week.
- Table: item (id, title; Casper's words verbatim when he captured it), type (bug in red, "bug · blocks use"),
  release, age. **Bugs first, then oldest first.** 25 rows, then **Show all 103**.
- Triage actions are the PO's, with the board tools; the note says so. Casper's own gate here is the release.
- Empty: "Nothing to triage in BobNet. Capture something with + Capture; it lands here."

### Capture (dialog from **+ Capture**) (capture 6, bugs 1, 3)
- **One field**, focused: "What is it? A title and a sentence is enough." Project (preset from the screen
  you're on; capture always has a project). **Is it a bug? No / Bug**; Bug adds **Where: staging / production**
  and **Blocks use**. The line under it says where it goes, and that a blocks-use bug also goes on Waits on you.
- Capture → toast "Captured as DRAFT-109 in Helix's triage list (, and on Waits on you)". Never a question
  back. The title is the first sentence; the full text is kept as Casper's words.
- Phone: bottom sheet, 16 px text (no zoom on focus), full-width buttons.

### States (`#states`)
Board unavailable (red banner: since when, showing what it last said, captures wait on the device), loading,
nothing waits on you, a project with no releases, a capture while the board is down.
