# 6. Board changes as requests to the project's PO (deferred)

**State:** deferred by the frame (Casper, 2026-11-13). Recorded so the earlier capabilities leave
room for it.

**What it is:** from the dashboard, Casper asks for a change to a board (reorder features, move a
feature between releases, edit a title or criteria). BobNet sends it as a request to that
project's backlog product owner, who makes it with the project's own tools. BobNet never writes it.

## Criteria to keep in mind now

- A request is a message to the board's writer, with the item, the change and Casper's words
  verbatim. (Picard input: "board edits wanted from the UI are requests to Picard, which fits")
- The request and its answer are visible next to the item until the board shows the change.

## Must not break

- One writer per board file. The UI is never a writer.
- Release scope and the order of releases are Casper's gates. A request to change them is Casper
  deciding, so it goes to the PO as a ruling, not a question.
